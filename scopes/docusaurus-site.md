# Docusaurus Site Layout

## Purpose

> **Scope:** Document work inside a Docusaurus documentation site - a React-based static site
> generator whose docs live in a `docs/` directory and whose sidebars are autogenerated from
> frontmatter
> **Key items:** autogenerated sidebars, `sidebar_position` frontmatter, underscore partials,
> `slug` stability, MDX tolerance

A Docusaurus site renders Markdown and MDX content into a documentation website.

Sidebars are autogenerated from the file and folder structure unless an explicit
`sidebars.js` overrides them.

Load this file when the task creates or edits pages inside such a site.

## Detection

A repository matches this scope when it contains all of the following:

- a `docusaurus.config.js`, `docusaurus.config.ts`, or `docusaurus.config.mjs` file, at the
  repository root or under a `website/` directory
- a `docs/` or `website/docs/` directory holding content pages
- optionally `src/pages/` and a `sidebars.js` or `sidebars.ts`

The configuration file is the strongest signal.

## Directory Roles

| Path                  | Role                                              |
|-----------------------|---------------------------------------------------|
| `docusaurus.config.*` | Site configuration - edit only when the task asks |
| `docs/`               | Documentation content pages                       |
| `blog/`               | Dated blog posts                                  |
| `src/pages/`          | Standalone pages, including React components      |
| `i18n/<locale>/docs/` | Translated copies of the docs pages               |
| `static/`             | Static assets served at the site root             |
| `build/`              | Generated output - never edit                     |

## Page Conventions

Docs pages use Markdown, `.md`, or MDX, `.mdx`.

A page carries YAML frontmatter, follow `conventions/markdown-dialects.md` - preserve its keys.

Frontmatter keys the generator reads:

- `title` - the sidebar and page title.
- `sidebar_position` - the position of the page in an autogenerated sidebar.
- `sidebar_label` - the sidebar text when it differs from the title.
- `slug` - the URL path segment, decoupled from the filename.
- `description` - the page meta description.
- `tags` - the page tags.

Files and folders prefixed with an underscore, for example `_partials/` or
`_sidebar-annotation.md`, are treated as partials and excluded from routing - do not remove the
prefix and do not edit them unless the task names them.

MDX pages follow the Markdown rules with `import` statements and JSX components treated as
opaque blocks preserved exactly - never reformat component markup, a broken import breaks the
build.

The `docs/` directory tree defines default URLs - keep a page's `slug` frontmatter stable when
renaming a file, otherwise the permalink breaks.

## Sidebar Registration

Adding a page usually requires no registration - autogenerated sidebars pick up new files.

Control the position with `sidebar_position` frontmatter on the page instead of touching
configuration - the default order is alphabetical by filename when positions are absent.

When an explicit `sidebars.js` or `sidebars.ts` exists, add the entry there, following the
file's existing type name and category structure.

Removing a page removes its sidebar entry automatically, but removes its explicit entry from
`sidebars.js` too when one exists.

## Document Types In This Scope

| File or directory                    | Type or handling                                   |
|--------------------------------------|----------------------------------------------------|
| Docs pages                           | `technical-document` type                          |
| Tutorials, guides                    | `article-text` type                                |
| Blog posts                           | `article-text` type with a date-prefixed filename  |
| `i18n/<locale>/` pages               | Translation - the target `languages/` file applies |
| `docusaurus.config.*`, `sidebars.js` | Build configuration - edit only when asked         |
| `src/pages/` components              | Code and React pages - not documents               |
| `build/`                             | Generated output - never edit                      |

## Building

Running `npm start` or `npm run build` is out of scope unless the request asks for it.

Report frontmatter keys added and sidebar entries changed in the delivery summary so the user
can rebuild.
