# Contribución a <Proyecto>

Gracias por su interés en contribuir a <Proyecto>.

Este documento explica cómo notificar problemas,
instalar el proyecto y enviar cambios.

## Formas de contribuir

- Notificar errores y pedir funcionalidades en el gestor de incidencias.
- Mejorar la documentación.
- Enviar cambios de código mediante pull requests.

## Notificación de problemas

Busque las incidencias existentes antes de abrir una nueva.

Notifique una incidencia por problema e indique la versión, el entorno,
los pasos reproducibles y el comportamiento esperado y observado.

## Entorno de desarrollo

```bash
git clone <url-del-repositorio>
cd <proyecto>
<comando de instalación>
<comando de verificación>
```

Ejecute las verificaciones del proyecto antes de abrir una pull request.

## Pull Requests

- Mantenga cada pull request centrada en un solo cambio.
- Siga la convención de mensajes de commit del proyecto.
- Añada o actualice las pruebas para los cambios de comportamiento.
- Mantenga las verificaciones de CI en verde.

## Contribuciones asistidas por IA

Declare cuándo un informe o un cambio se ha creado con ayuda de la IA.

Compruebe usted mismo cada resultado producido por la IA antes de notificarlo -
no pegue una salida en bruto de la IA en una incidencia o una pull request.

Debe entender y asumir el código enviado - las contribuciones asistidas por IA
siguen los mismos requisitos de estilo, pruebas y licencia que cualquier otra
contribución.

## Licencia

Al contribuir, usted acepta que sus contribuciones se publiquen bajo la licencia
del proyecto.

## Código de conducta

Este proyecto sigue su código de conducta - vea `CODE_OF_CONDUCT.md`.

## Obtener ayuda

Plantee sus preguntas en <canal> en lugar de abrir incidencias para soporte.
