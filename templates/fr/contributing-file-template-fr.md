# Contribution à <Projet>

Merci de votre intérêt à contribuer à <Projet>.

Ce document explique comment signaler les problèmes,
installer le projet et soumettre des modifications.

## Comment contribuer

- Signaler les bogues et demander les fonctionnalités dans le gestionnaire de tickets.
- Améliorer la documentation.
- Soumettre les modifications de code par des pull requests.

## Signalement de problèmes

Recherchez les tickets existants avant d'en ouvrir un nouveau.

Signalez un ticket par problème et indiquez la version, l'environnement,
les étapes reproductibles ainsi que le comportement attendu et constaté.

## Environnement de développement

```bash
git clone <url-du-depot>
cd <projet>
<commande d'installation>
<commande de vérification>
```

Exécutez les vérifications du projet avant d'ouvrir une pull request.

## Pull Requests

- Gardez chaque pull request centrée sur une seule modification.
- Suivez la convention de messages de commit du projet.
- Ajoutez ou mettez à jour les tests pour les changements de comportement.
- Gardez les vérifications CI au vert.

## Contributions assistées par IA

Signalez quand un rapport ou une modification a été créé avec l'aide de l'IA.

Vérifiez vous-même chaque résultat produit par l'IA avant de le signaler -
ne collez pas de sortie brute de l'IA dans un ticket ou une pull request.

Vous devez comprendre et assumer le code soumis - les contributions assistées
par IA suivent les mêmes exigences de style, de tests et de licence que toute
autre contribution.

## Licence

En contribuant, vous acceptez que vos contributions soient placées sous la
licence du projet.

## Code de conduite

Ce projet suit son code de conduite - voir `CODE_OF_CONDUCT.md`.

## Obtenir de l'aide

Posez vos questions sur <canal> au lieu d'ouvrir des tickets pour le support.
